# Панель 1.2: права и обновление

## Права отделены от названий ролей

| Область | Права |
|---|---|
| Просмотр конфигурации | `VIEW_SERVER_SETTINGS` |
| Параметры панели | `MANAGE_PANEL_SETTINGS` |
| Параметры сервера | `MANAGE_SERVER_SETTINGS` |
| Системная безопасность | `MANAGE_SECURITY_SETTINGS` |
| Внешние интеграции | `MANAGE_INTEGRATIONS` |
| Технические работы | `MANAGE_MAINTENANCE` |
| Белый список / операторы | `MANAGE_WHITELIST` / `MANAGE_OPERATORS` |
| Серверный Preview | `MANAGE_PREVIEW` |
| Vesuvio: базовые / подробные данные | `VIEW_VESUVIO` / `VIEW_VESUVIO_ADVANCED` |
| Vesuvio: действия / образцы / модели | `MANAGE_VESUVIO` / `REVIEW_VESUVIO_SAMPLES` / `MANAGE_VESUVIO_MODELS` |
| API-ключи, вебхуки и доставки | `MANAGE_API` |

Личные настройки и безопасность собственного аккаунта доступны через свою сессию. `MANAGE_ADMINS` и имя «Администратор» не предоставляют права настройки панели/сервера. Управляющий (`is_owner`) сохраняет полный доступ. Существующие пользовательские роли автоматически новыми полномочиями не наделяются: назначьте их явно. Интерфейс скрывает недоступные разделы, сервер проверяет каждое действие независимо от интерфейса.

Ответы настройки не раскрывают секретный адрес Discord webhook. Пустое поле сохраняет действующий секрет; отдельное действие очистки удаляет его. Списки вебхуков показывают адрес сервера и признаки заполнения без токена URL и подписи. Создавать API-ключ с полным `*` может только управляющий; остальные явно выбирают права, которыми обладают сами.

## Повторные запросы и конфликты

Frontend объединяет одинаковые одновременные действия и временно блокирует кнопку. `Idempotency-Key` сохраняется для неизвестного результата. Сервер записывает намерение до изменения в `operations.db`; одинаковый ключ с другим содержимым отклоняется. После остановки незавершённая операция становится `UNCERTAIN`, а не выполняется повторно. Статус доступен только её автору через `GET /api/operations/<ключ>` с актуальными правами.

Секреты, выдаваемые один раз (новый API-ключ, резервные коды, секрет Preview), не сохраняются в ответах журнала. Повтор сообщает о завершённом действии, не создавая второй объект. Потерянный ключ отзовите, потерянную песочницу удалите через её список, затем создайте новую.

Редактор дела и исправление бана отправляют версию. Конкурирующее изменение возвращает 409 и сохраняет черновик в браузере; обновите данные и осознанно примените изменения. История исправления бана хранит автора изменения, объяснение, прежние/новые причину и срок. Исходные автор и источник не заменяются; активное наказание синхронизируется с Bukkit на основном потоке.

Очередь Discord хранится в SQLite. После остановки во время отправки результат неизвестен — автоматической повторной отправки нет. На странице доставок сотрудник сверяет Discord и с объяснением подтверждает доставку либо отмечает её отсутствие; только затем доступен повтор. Личные служебные уведомления соблюдают права, предпочтения и тихие часы; уведомления наказанному игроку отправляются независимо.

## Миграция и установка

1. Остановите сервер; сохраните копии папок трёх плагинов.
2. Замените LoveCore, Vesuvio и LoveWebAdmin проверенными JAR соответствующих PR, запустите сервер.
3. До изменения существующей SQLite создаются `database-before-panel-v3.db` и `moderation.db.before-panel-v3.db`. Существующие дела, права и источники сохраняются. Ошибка создания копии прекращает открытие миграции.
4. Старые колонки смен остаются историческими для совместимости, но команд, кнопок и проверки «на смене» больше нет. Старые endpoints отвечают 410. Устаревшие slash-команды удаляются по имени, команды других Love-плагинов сохраняются.
5. В Vesuvio больше нет отдельного порта, dashboard или `web.*`. Новый WebAdmin получает функции через версионированную службу; отсутствие/старая версия показываются объяснением, без обращения к закрытым классам.

Схема сохраняет совместимость публичных API Love-плагинов; новые возможности Core/Vesuvio имеют defaults и внутренние адаптеры. Неподдерживаемая операция не отправляется другим способом в рабочий канал.

## Проверка выпуска

- Java 25: Maven verify LoveWebAdmin и Vesuvio; полный LoveCore verify — GitHub CI (локальный репозиторий Citizens отвечает 403).
- Node: модель Preview и граф локальных импортов; Playwright: рабочее хранилище/сеть, 2FA, навигация, дела, исправления и мобильный портал.
- Новые регрессионные сценарии: конкурирующие запросы, остановка, роли/отзыв доступа, отсутствие секретов в ответах, авторизация файлов, одноразовые ссылки, версии и возврат предметов.
- Без живого Paper/Purpur и настроенных тестовых ID нельзя подтвердить нативные игровые изменения, полный запуск/остановку на настоящем сервере, доставку/вложения/ответы настоящего Discord и поведение под нагрузкой. Эти проверки не объявляются пройденными на основании моделей.

Для неизвестного результата действия в панели появляется «Проверить результат». Сверка не повторяет исходное действие: сотрудник просматривает данные, подтверждает выполнение либо его отсутствие с объяснением. Отметить можно только собственную завершившуюся неопределённую операцию с актуальными правами; выполняющаяся операция не изменяется. Ключи неопределённых намерений не заменяются из-за истечения времени и не выбрасываются при переполнении браузерного лимита.
