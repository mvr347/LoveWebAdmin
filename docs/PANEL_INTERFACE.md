# Интерфейс панели

Встроенная панель использует красную палитру и одинаковую иконку куба во вкладке и боковом меню. Жалобы, апелляции и поддержка разделены; баны, муты и проверки находятся в «Баны и ограничения».

Карточка справа показывает краткую сводку. «Открыть дело» открывает выдвижную панель с перепиской, материалами и решением. Настройки тоже открываются справа. Закрытие вложенного выбора жалобы сохраняет форму бана.

Списки загружаются ограниченными порциями, чтобы история обращений не занимала всю память браузера. «Более ранние» и «Более новые» переключают порцию; поиск и фильтр применяются к текущей порции. Выбор, фильтр и страница сохраняются при возврате в раздел.

Назначение ответственного читается из SQLite пакетным запросом для текущего списка. Доступ проверяется отдельно для каждого типа обращения. Тестовая модель остаётся только в Preview; основной интерфейс работает через API сервера. Темы поддержки и уведомления Discord настраиваются существующим конфигом.

## Рабочие разделы и настройки

Игровой журнал и безопасность игровых аккаунтов отделены от веб-журнала и сессий сотрудников. Категория «Вебадмин» содержит сотрудников и роли, авторизацию панели, веб-журнал и настройки сайта. Доступность каждого раздела зависит от его прав. Дашборд не перерабатывался.

Настройки панели открываются страницей с вкладками. Личные настройки открываются отдельно через профиль сотрудника: тема, начальная страница, компактность строк, уменьшение анимаций и запоминание фильтров. Выбранная тема применяется до загрузки приложения и сохраняется в браузере и профиле. При недоступном хранилище страница продолжает работать без постоянного сохранения.

Веб-журнал буферизует изменения до нажатия «Показать», сохраняя читаемые строки. Игровая авторизация поддерживает подсказки ников с выбором стрелками, Enter и Escape. Подсказки без права просмотра досье возвращают только имена.

Уведомления разделены на новые и все. Одинаковые записи объединяются в карточку со счётчиком; прочтение применяется ко всем исходным записям. Исходные записи сохраняются.

## Права и совместимость

Редактор ролей группирует права: игроки, обращения, наказания, античит, сервер и статистика, вебадмин, опасные возможности. Поиск работает по названию и описанию. Предпросмотр показывает разделы и действия, а не гарантирует доступ к каждому конкретному делу.

| Было | Теперь в интерфейсе | Хранение и API |
|---|---|---|
| Плоский список прав | Группы, поиск, фильтр выданных | Идентификаторы сохранены |
| VIEW_PLAYER_INVENTORY, CONFISCATE_ITEMS, RESTORE_ITEMS | Скрыты из редактора | Существующие значения сохраняются при редактировании |
| MANAGE_PLAYERS | Администрирование досье, с пояснением отдельных действий | Без расширения прав |
| MANAGE_API | Служебные подключения | Без расширения прав |
| Новое управляющее право без просмотра | Включается необходимый просмотр | Сервер проверяет зависимости и право делегирования |

Старые роли не получают новые права при запуске или сохранении без изменения состава. Новые действия добавляют необходимые права просмотра. Существующий необходимый просмотр нельзя снять, оставив зависимое действие. Изменение только названия роли не стирает права или привязку внешней группы.

Сервер запрещает редактирование собственной роли обычным сотрудником, выдачу прав выше своих и работу с более привилегированной ролью. Управляющий сохраняет полный доступ; его роль нельзя удалить. Изменять привязку внешней группы может только Управляющий. Проверки действуют в API ролей, приглашениях и назначении ролей сотрудникам. Отозванные права проверяются по актуальной роли, а не по старой сессии.


## Наказания и обращения: обновление 2026-11-08

- Раздел «Наказания»: крупные вкладки «Баны», «Муты», «Заморозки», отдельные действующие записи, оформление, история и архив материалов банов. Поиск по игроку/причине, сотруднику и датам. История загружается страницами по 25 записей; лишняя пагинация скрыта. Архив отображает имена материалов без внутреннего пути сервера.
- Смена режима сохраняет фильтры и не пересоздаёт всю страницу. Автоматический опрос раз в 8 секунд приостанавливается при открытой форме, скрытой вкладке или фокусе на действиях строки. Неизменившиеся строки сохраняют DOM.
- Сводка дела — статичный блок, действия назначения и решения не спрятаны в сворачиваемом разделе. Поддержка имеет отдельную переписку; закрытие требует причины. Закреплённая кнопка закрытия переводит к этому полю, не обходит подтверждение.
- Общий поиск включает игроков, баны, жалобы, апелляции и поддержку, с проверкой прав на сервере. Запросы ограничены по длине и количеству результатов.
- «Уровень доверия» показывает русскую категорию и число. Наведение или фокус открывает факторы фактического расчёта. Нулевой показатель сохраняется; оценка не является доказательством нарушения.
- Раздел моделей и типов проверок удалён из сайта. Совместимые серверные API остаются доступны только Управляющему; обычные сигналы и очередь наказаний — по существующим правам.
- ANSI-коды и старые коды цвета удаляются из отображения серверного журнала. Веб-ассеты повторно проверяются через ETag; при перезапуске версия меняется.

«Ожидание» отмечает, от кого нужен ответ: игрока или сотрудника. Сроки используются для напоминаний и эскалации, не для автоматического решения. «Шаблоны» — заготовки ответа/решения: вставка текста не отправляет сообщение и не применяет наказание без отдельного подтверждения.

Проверки интерфейса выполняются в браузерной песочнице, включая ширину 390 и 1440 пикселей. Проверка заморозки на живом Paper/Purpur и доставка в настоящем Discord требуют отдельного серверного прогона.


## Карточки наказаний и порядок фильтров

Раздел наказаний использует общую компоновку обращений: список слева, выбранная карточка справа. В карточке находятся причина, сотрудник, дата, срок и допустимые действия. При пустом результате карточка скрывается; на телефоне она расположена под списком. Сохраняются виды наказаний, отдельное оформление ручного бана, фильтры, история, архив и страницы по 25 записей.

В жалобах, апелляциях и поддержке фильтры идут в порядке «Все → Новые → В работе». При первом открытии выбран «Все», а последующие переходы сохраняют выбор сотрудника. В античите первая вкладка — «Поток нарушений», далее волна наказаний, наблюдение и журнал.


## Разбор срабатываний античита

В потоке появились «Чит» и «Чистый». Это решение по конкретному событию, а не постоянный статус игрока и не автоматический бан. Нужно обоснование; сохраняются сотрудник, дата, версия и история решений в базе Vesuvio. При конфликте версий старый экран не перезаписывает новое решение. История срабатывания не удаляется, текущий VL сам по себе не сбрасывается.

Права: просмотр `VIEW_VESUVIO_ADVANCED`, разбор `MANAGE_VESUVIO`. Технический раздел моделей не возвращается. Кнопка «Образцы для разбора» открывает активные ML-образцы и передаёт метку в существующее обучение соответствующего домена кликов/прицеливания. Исторические события без исходного вектора не превращаются в фиктивные обучающие образцы.

Нужны обновлённые LoveWebAdmin и Vesuvio с capability `violation-reviews`. Старые версии остаются доступны для чтения, а кнопки разбора событий без постоянного ID отключены. Время поддерживает секунды и миллисекунды Unix; VL округлён до двух знаков и не называется уверенностью.


### Баны для разбора и название «Чистый»

Отметка `legit` в интерфейсе называется «Чистый». Значение API/базы сохранено для совместимости.

«Античит → Баны для разбора» показывает окончательно оформленные баны с причиной «Чит/Читы» или названием настроенного пресета с ID `cheats`. Черновики, отменённые предварительные баны и посторонние причины не добавляются. Очередь строится непосредственно по SQLite наказаний — повторных копий и потерь при недоступном античите нет. Сначала показаны записи без решения, страницы ограничены 25 элементами. Снятые и истёкшие баны отмечены отдельным состоянием.

Для просмотра нужны `VIEW_BANS` и `VIEW_VESUVIO_ADVANCED`, для решения дополнительно `MANAGE_VESUVIO`. Вердикт, причина, сотрудник и история версий сохраняются атомарно. «Чистый» в разборе не снимает бан и не создаёт постоянное исключение из проверок. Кнопка наказания открывает вложенную карточку, после закрытия очередь сохраняется. Для обучения требуется отдельный проверенный ML-образец.
