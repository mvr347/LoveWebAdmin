# Работа с наказаниями: исправления и дальнейшие улучшения

## Реализовано

- Выбор жалобы, просмотр изображения и подтверждение не уничтожают родительскую форму. Escape, крестик, отмена и фон закрывают верхнее окно. Возвращаются фокус, введённые поля, срок и выбранная причина.
- Окно выбора объясняет пустой результат и предлагает вернуться к бану без жалобы. Показываются открытые жалобы на выбранного игрока; доступны серверный поиск, страницы и проверка номера вместо системного prompt. Пагинация скрыта, когда не нужна.
- Форма объясняет недостающие поля до отправки. Итоговая проверка показывает игрока, срок, причину и закрываемую жалобу. Повторные нажатия не запускают второе подтверждение/отправку. Ошибка сохраняет форму. Закрытие формы не означает отмену уже отправленной операции.
- Запоздалые ответы закрытого окна не меняют новое окно. Выход из аккаунта закрывает связанные формы и подтверждения; горячие клавиши разделов не уничтожают открытый редактор.
- Короткий контекст игрока заменяет загрузку всей истории банов. Запросы одного игрока не повторяются на change/blur; обращения для контекста и подсказок используют один ограниченный кэш на время формы. Поиск ника игнорирует устаревшие ответы и снимает обработчик document при закрытии формы.
- Для привязки нужны права обработки жалоб и банов. Сервер проверяет игрока и состояние жалобы; привязка существующего бана и закрытие жалобы — одна транзакция с откатом при ошибке. Некорректный номер не превращается в создание другого бана.
- Текст жалоб и значения HTML-атрибутов экранируются. Ссылки доказательств передаются как данные вместо вставки в JavaScript обработчика. Чувствительные API-ответы получают no-store; политика браузера запрещает object и подмену base.
- Исправлена ошибка currentBan в деталях активного бана. Таблица и карточка показывают фактический срок вместо безусловного «Бессрочно».

Это сохранение формы в открытом интерфейсе, а не обещание восстановления после перезагрузки браузера. Уже отправленное действие сверяется через существующий журнал операций.

## Предлагаемый следующий этап — пока не реализован

1. **Одна карточка дела.** Сверху игрок, состояние, сотрудник/Система/Безопасность/Античит, срок и ближайшее действие. Далее три понятных раздела: «Переписка», «Доказательства», «История». Детали наказания и жалобы открываются из неё без смены контекста.
2. **Очередь по следующему действию.** «Нужен мой ответ», «Ожидаем игрока», «Ожидает оформления», «Завершено» вместо нескольких пересекающихся списков. На карточке — конкретное объяснение, кто и что делает дальше.
3. **Одна основная кнопка.** «Взять дело», «Запросить уточнение» или «Принять решение» в зависимости от состояния. Редкие и опасные действия раскрываются отдельно, с объяснением последствий и проверкой текущей версии дела.
4. **Предсказуемое возвращение.** Строка «Жалобы → Дело №… → Изменение наказания», сохранение фильтра/страницы и понятное предупреждение при попытке покинуть несохранённую форму. Вложенные окна используются только для кратких выборов.
5. **Черновики без лишних секретов.** После согласования — серверный черновик на сотрудника и дело с ограниченным сроком хранения, без токенов и файлов в localStorage. После входа предложить восстановление; выход не должен показывать его другому сотруднику.

Сначала стоит сделать единую карточку и очередь: это уменьшит необходимость помнить, в каком разделе находится нужное действие, при сохранении функций панели.

## Проверка

Maven verify на Java 25, Node-тесты и Playwright с настоящими HTML/JS панели в изолированном Preview. Регрессии покрывают отмену вложенных окон, подтверждение и отказ записи, устаревшие ответы, повторные клики, проверку жалобы, безопасный вывод и очистку обработчиков; серверные тесты — права, целостность привязок, принудительную ошибку SQLite и ограниченные запросы.

Проверки Preview не являются проверкой реального Discord или нагрузки живого Paper/Purpur. Замер ускорения в миллисекундах и общего снижения серверного heap не заявляется.
