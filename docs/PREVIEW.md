# Превью панели и обязательная 2FA

`debug-mode` и `security.debug-mode` удалены из настроек. Их старые значения не отключают 2FA и очищаются при запуске. Прежний метод `isDebugMode()` сохранён только для бинарной совместимости и всегда возвращает `false`. Старое поле API `debugMode` отклоняется. Действующий порядок подтверждения доверенного устройства сохраняется: код требуется при смене IP или по истечении срока доверия, регистрация и первичная настройка обязательно подтверждают TOTP.

Публичное подтверждение 2FA дополнительно требует одноразовый challenge, выданный после верного пароля. Он привязан к аккаунту и IP, действует пять минут, ограничен пятью попытками. Неверный код первичной настройки больше не уничтожает токен настройки. Один TOTP нельзя использовать одновременно в нескольких запросах.

## Включение

В `plugins/LoveWebAdmin/config.yml`:

```yaml
preview:
  enabled: true
```

Либо включите «Превью интерфейса» в общих настройках настоящей панели. Откройте `/preview/` на том же адресе. Ссылка также появляется на странице входа. По умолчанию превью выключено.

Это отдельная песочница **на синтетических данных вашей вкладки**, использующая обычные экраны панели. Она не отключает защиту настоящего входа. Настоящие токены, браузерные настройки, SQLite, игроки, команды и Discord не используются. Даже при сбое клиентского симулятора CSP запрещает подключения к настоящему API. На сервере `/preview/api/*` ничего не выполняет.

## Проверка механик

В верхней плашке выберите тестовую роль: Управляющий, Модератор или Наблюдатель. Ограничения роли применяются и к действиям симулятора.

В «Сценариях» доступны:

- Создание бана, жалобы и апелляции подтверждённого либо непривязанного игрока.
- Ответ игрока из тестового Discord, запрос и ответ на уточнение жалобы.
- Ошибка доставки, повтор, тихие часы и обработка очереди.
- Возврат тестовых игроков онлайн после кика или убийства.
- Экран входа и первичная настройка. Демопароль `PreviewOnly!25`, демонстрационный код `123456`. Этот код проверяется только локальным симулятором; он не принимается настоящей панелью. QR в превью демонстрационный.

Дальше используйте обычные кнопки: начать/завершить смену, выдать/снять бан, принять/отклонить апелляцию или сократить срок, назначить дело, добавить внутреннюю заметку, объединить жалобы, изменить шаблон, изъять/вернуть предмет, изменить тестовые роли и настройки. В «Сценариях» видна лента тестового Discord. Служебные уведомления ожидают смены, уведомления игроку о бане не задерживаются тихими часами.

Состояние сохраняется при переходах и обновлении страницы. «Сбросить» очищает только песочницу; настоящая сессия и данные остаются прежними. Другие вкладки имеют отдельное состояние. «В настоящую панель» возвращает в обычный интерфейс с его собственной авторизацией.

Превью проверяет интерфейс и моделируемые переходы состояний. Подключения к реальным Minecraft-плагинам, доставку настоящим ботом и изменения игрового мира оно намеренно не выполняет. Неизвестный маршрут сообщает об отсутствии модели и никогда не передаётся настоящему API.

## Проверки разработчика

- `mvn verify` на Java 25 — в том числе отсутствие обхода через прежние флаги, регистрацию, приглашение, настройку владельца и прямой запрос 2FA; границы HTTP-превью и CSP.
- `npm ci && npm test` — сценарии и ограничения симулятора.
- `npx playwright install chromium && npm run test:browser` — обычные экраны в Chromium, вход, бан, смена, навигация, переписка, инвентарь, роли и изоляция от настоящих запросов/хранилища.

Ресурсы JavaScript больше не проходят подстановку Maven `${...}`. Фильтруется только `plugin.yml`: это также исправляет старые испорченные URL действий с жалобами и уведомлениями.
