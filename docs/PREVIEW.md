# Preview и обязательная 2FA

Обход входа удалён. Старые `debug-mode` и `security.debug-mode` не отключают 2FA; `isDebugMode()` оставлен совместимым и возвращает false. Настоящий вход, доверенные устройства и подтверждение регистрации остаются рабочими.

## Два режима

В `config.yml` включите `preview.enabled: true`, перезапустите сервер и откройте `/preview/` на адресе панели. Переключатель Preview в параметрах панели требует отдельного `MANAGE_PREVIEW`.

**Локальный режим** — синтетические данные вкладки, без запросов к рабочему API и без Discord. Можно проверить экраны, роли, бан/исправление/разбан, дела, заметки, доказательства, инвентарь, фильтры и личный кабинет. Демопароль — `PreviewOnly!25`, локальный код — `123456`. Это модель интерфейса, она не подтверждает работу настоящего сервера или бота.

**Серверный Preview** создаёт отдельные SQLite, конфигурацию, доказательства, очередь доставок и журнал операций в `plugins/LoveWebAdmin/preview/<случайный ID>/`. Нужна настоящая сессия сотрудника после обычного входа и право `MANAGE_PREVIEW`. В плашке нажмите «Серверный Preview». После создания браузер отправляет запросы только в `/preview/api/<ID>/…` с отдельным секретом. Реальный Bearer-токен не является секретом песочницы, виртуальная роль не предоставляет доступ к рабочей панели.

Сервер проверяет тестовые права и изменения. Решения апелляций используют общую службу `AppealService`, доказательства — общий валидатор, личный кабинет — общий одноразовый обмен. Игровые действия, экономика, LoveAuth и показатели Vesuvio в песочнице **моделируются**: реальные команды, предметы, деньги и игроки не изменяются. Подмена клиентского снимка не изменяет серверную песочницу.

До 8 песочниц одновременно, срок сессии 24 часа. Доступ проверяется по действующему аккаунту и праву владельца. «Мои серверные песочницы» позволяет удалить собственные контексты, в том числе если браузер потерял секрет при сетевом сбое. «Удалить»/«Сбросить» закрывает только их тестовые тикеты и удаляет их данные. Остановка плагина сохраняет активные контексты для восстановления. Чужие песочницы не отображаются.

## Настоящий тест Discord

Установите LoveCore из PR #40 и настройте его бота. В LoveWebAdmin укажите **отдельные** тестовые категорию и канал:

```yaml
preview:
  enabled: true
  discord:
    category-id: "123456789012345678"
    channel-id: "234567890123456789"
    allowed-user-ids:
      - "345678901234567890"
```

Замените примеры действительными Discord ID и перезапустите плагин. Боту нужны права просмотра категории, создания каналов, отправки сообщений, вложений и изменения прав тикетов. Тестовая категория не должна совпадать с рабочими категориями апелляций/поддержки LoveCore; Core отклоняет такое совпадение. Пустые настройки отключают настоящую отправку; подстановки рабочего канала нет.

Жалобы и апелляции создают приватные тестовые обращения с `[ТЕСТ]` и пространством имён `preview:`. Бан отправляется в тестовый канал; тестовые ЛС — только перечисленным `allowed-user-ids` (не более 10). Только эти пользователи могут передавать ответы из тестового тикета в песочницу. Сообщения, вложения и решения не попадают в рабочие дела. Доказательство с видимостью «Только сотрудникам» в Discord игроку не отправляется.

«Проверить доставку в Discord» показывает сохранённый результат. «Принято Discord» означает полученный ID сообщения/API-подтверждение, а не прочтение человеком. При неизвестном результате автоматический повтор блокируется; сверяйте тестовый Discord. Локальная лента всегда обозначает моделирование. Тихие часы в локальном режиме моделируют правила служебных уведомлений; они не задерживают тестовое уведомление игроку о бане.

## Центр проверок

В «Сценариях» выберите «Запустить проверки сервера». Прогон работает в дочернем временном хранилище и не изменяет открытую песочницу. Он проверяет группы API, роли и запрет повышения прав, бан/исправление и защиту от дубля, решение апелляции, версии дела, приватность доказательств, одноразовую ссылку и отказ неверной 2FA. Игровые операции отдельно отмечены как смоделированные. Временные данные удаляются после прогона.

Настоящая доставка и обратный ответ Discord помечены как требующие отдельной проверки. Для них создайте тестовую жалобу/апелляцию, дождитесь статуса, ответьте в созданном канале разрешённым аккаунтом и обновите дело. Для изображений добавьте скриншот с видимостью «Также автору обращения». Успех локальных/серверных моделей не заменяет эту проверку.

«Проверить вход с 2FA» выводит отдельный **тестовый** TOTP-секрет. В серверном режиме нужен настоящий код из него; `123456` не является обходом. Секреты рабочего аккаунта не используются.

## Проверка разработчика

Java 25: `mvn verify`; браузер: `npm ci --ignore-scripts && npm test && npm run test:browser` (перед первым запуском `npx playwright install chromium`). Модель и граф ES-модулей тестируются отдельно; Playwright проверяет изоляцию от рабочего API/хранилища, вход, навигацию, дело/доказательства, исправление бана и мобильный личный кабинет. Проверки на настоящем Paper/Purpur и Discord требуют настроенного тестового окружения.
