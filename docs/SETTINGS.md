# Настройки сайта и config.yml

Версия 1.3.2, схема конфигурации 3. Общие настройки открываются в разделе «Настройки» или через шестерёнку. Личные параметры доступны по кнопке «Мои настройки» и через профиль сотрудника. Наличие разделов зависит от отдельных прав сотрудника, а не названия роли.

| Раздел сайта | Что задаётся | Где в config.yml | Право изменения |
|---|---|---|---|
| Мои настройки | Оформление и предпочтения сотрудника | Хранится в профиле SQLite | Свой профиль |
| Мои уведомления | Ваши ЛС о жалобах и апелляциях | Профиль SQLite, не общий конфиг | Свой профиль и подтверждённая привязка |
| Сайт и сессии | Включение сайта, адрес, порт, внешний URL, сессии и журнал | `web`, `logs` | `MANAGE_PANEL_SETTINGS` |
| Бот и обращения | Сообщение с тремя кнопками, очередь, руководство, сроки, каналы и тихие часы | `discord` | `MANAGE_INTEGRATIONS` |
| Preview и тесты | Песочница и отдельная тестовая категория Discord | `preview` | `MANAGE_PREVIEW` |
| Пароль и вход | Личный пароль, сессии и резервные коды 2FA | Учётная запись сотрудника | Свой профиль |
| Правила входа | Общие требования к паролям, защита от перебора, привязка сессий к IP | `security` | `MANAGE_SECURITY_SETTINGS` |
| Команды веб-консоли | Запрещённые команды веб-консоли | `security.command-blacklist` | `MANAGE_SECURITY_SETTINGS` |
| Обслуживание панели | Доступность сайта персоналу и сообщение сотрудникам | `security.maintenance` | `MANAGE_MAINTENANCE` |

Личные настройки не меняют каналы и роли сервера. Сотрудник с правом интеграций может читать и сохранять свои параметры без отдельного права просмотра остальных настроек; адрес сайта ему менять нельзя.

## Игровой сервер и навигация

В разделе «Настройки» отдельная группа «Игровой сервер» открывает белый список и операторов Minecraft. Эти настройки не меняют роли панели. Белый список доступен по `MANAGE_WHITELIST`, операторы — по `MANAGE_OPERATORS`; интерфейс не запрашивает недоступный список. Выдача/снятие прав, изменение режима и состава белого списка подтверждаются с фактическим ником игрока. Повторные нажатия блокируются на время операции.

Боковое меню разделено на «Работа», «Обращения», «Модерация», «Сервер» и «Вебадмин». В «Наказаниях» отдельно выбираются баны, муты и заморозки, затем действующие записи, оформление или история. Наказания — клавиша 6, настройки — 0. На небольшом экране доступно горизонтальное меню без кнопки-бургера.

Обслуживание **веб-панели** не останавливает Minecraft и не запрещает вход игроков. Личные настройки не изменяют общие правила безопасности. Инвентарь и действие очистки инвентаря удалены из досье игрока; отдельная защищённая страница инвентаря и API сохранены.

## Рабочая панель обращений Discord

1. Настройте бота в LoveCore.
2. В «Бот и обращения» укажите **ID текстового канала** для сообщения «Жалоба / Апелляция / Мои обращения». Пустое значение отключает постоянное сообщение.
3. При необходимости задайте другой закрытый текстовый канал очереди персонала и Discord ID ролей руководства. Роли Discord не заменяют права сотрудника в панели.
4. Сохраните. Для смены каналов/руководства/сроков/тихих часов нужен перезапуск плагина или сервера: текущий обработчик продолжает работу с настройками запуска.
5. Откройте «Диагностику и публикацию панели»: там причина отсутствия сообщения и действие публикации. Неизвестный результат требует сверки; не удаляйте базу для повтора.

ID копируется в Discord через ПКМ → «Скопировать ID», после включения режима разработчика. Вставляйте его текстом. ID категории не подходит для сообщения. Списки содержат один ID на строку; сайт не преобразует длинные числа в неточные JavaScript Number.

Напоминания указываются в минутах. `0` отключает соответствующий порог; уведомление руководству не может наступать раньше напоминания сотруднику. Таймеры не закрывают дела и не меняют наказания. Тихие часы относятся к служебным ЛС, а не уведомлению наказанному игроку.

## Preview

Нужны разные ID: отдельная **категория** и **текстовый канал внутри неё**. Добавьте Discord ID тестировщиков, не роли и не Minecraft UUID. Канал Preview не может совпадать с рабочей панелью, очередью или каналами уведомлений. Пустые поля позволяют пользоваться локальной моделью без настоящих отправок.

Переключатель Preview применяется сразу; смена его маршрутизации требует перезапуска. Настоящие сообщения запускаются отдельно в серверной песочнице. Подробности и проверки — [PREVIEW.md](PREVIEW.md).

## Удалённые интеграции

Вебхуки и Telegram удалены из интерфейса и активной конфигурации. Уведомления обращений отправляет общий Discord-бот. При обновлении старые ключи удаляются после создания точной резервной копии исходного `config.yml`; обычный транспорт уведомлений переводится на `bot`. Резервная копия может содержать прежние секреты — храните её как приватный конфиг.

## Сохранение и обновление

Новые формы веб-панели, Discord и Preview отправляют только изменённые значения, блокируют повторное сохранение и сохраняют черновик при переключении разделов внутри открытых настроек. Некорректные ID, одинаковые каналы, неверные сроки и неподходящий адрес вебхука отклоняются до записи всей пачки. Успешный ответ показывает, нужен ли перезапуск.

Запись файла атомарная; ошибка сохранения не применяет значения к работающему плагину. При обновлении старый конфиг получает новые блоки и комментарии; пользовательские значения, списки и неизвестные настройки сохраняются. Исключение — явно удалённые настройки Telegram и устаревший дублирующий переключатель вебхука. До миграции создаётся `config.yml.backup-…`.

Адрес/порт/включение веб-сервера и внешний URL требуют перезапуска. Изменение минимальной длины применяется к новым паролям, не меняя существующие; допускается 12–32 символа, требования сложности остаются. Настройки сервера и песочницы используют общий валидатор; Preview не записывает рабочий конфиг.


## Вход и подтверждение чувствительных действий

Для настроенной учётной записи правильного пароля достаточно, если IP совпадает с последним адресом, подтверждённым через 2FA. При новом IP, первом входе или отсутствии подтверждения нужен код либо резервный код входа. Еженедельный повтор 2FA отменён; обычный вход не переписывает подтверждённый IP и время 2FA.

Смена собственного пароля требует текущий пароль и новый код 2FA в форме. Остальные сессии после смены завершаются, текущая сохраняется. Для перевыпуска резервных кодов, завершения других сессий, изменения сотрудников/ролей, настроек панели и доступа операторов появляется отдельное окно 2FA. Отмена сохраняет форму и не выполняет действие. Изменение темы, личных предпочтений и обычная модерация не требуют этого дополнительного окна.

Коды проверяются на сервере, защищены от повторного использования и перебора. Если код уже использовали для входа или другого действия, дождитесь следующего кода в приложении. Подтверждение действия не делает новый IP доверенным для последующего входа. Изменять доступ через технический API-ключ нельзя: требуется личная учётная запись сотрудника.
